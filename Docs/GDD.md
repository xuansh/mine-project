## 1. 概述

### 1.1 一句话概念

> 你驾驶一台小型挖掘机，从地表一路向矿区深处推进；挖得越深，矿石越值钱，岩层也越硬——用赚到的钱改装机器，再往下挖。

### 1.2 核心体验

玩家真正在享受的两件事，按优先级排序：

1. **推进的爽感**：看着矿格一格一格被吃掉、矿车往前挪、深度数字变大。
2. **构筑的成长**：把"挖得慢、油不够、装不下"这三个短板，用升级一件件补掉；再沿着**技能树**把机器改造成自己的流派（这条是本作的特色系统，见 4.6.1）。

### 1.3 设计支柱

所有后续设计决策都要能回到这三条，冲突时按顺序取舍：

| 支柱 | 含义 | 反面案例（不做） |
| --- | --- | --- |
| **P1 挖掘即反馈** | 每一次挖掘都有可感知的视觉/听觉/数字反馈 | 挖一格毫无动静、只是格子消失 |
| **P2 一次只做一个决定** | 单局中玩家每次只需要做一个有意义的选择 | 同时管理 5 种资源、3 条产线 |
| **P3 深度即进度** | 深度是最直观的进度条，替代复杂的关卡选择 | 用关卡列表、章节选择来推进 |

### 1.4 参考作品

- 《Mr. Mine》《Idle Miner Tycoon》：深度推进 + 数值成长的骨架。
- 《Motherload》：燃油/货舱/回程的取舍结构。
- 《Dome Keeper》《SteamWorld Dig》：单局节奏与"往下挖"的空间感。

> 本作不做放置挂机的离线收益，也不做自由 3D 建造。定位是**轻操作的推进型挖掘游戏**，单局 3–8 分钟，可随时暂停。

## 2. 玩家与平台

| 项 | 定义 |
| --- | --- |
| 目标玩家 | 喜欢"数值成长 + 短局推进"的休闲/中核玩家；单手可玩 |
| 平台 | PC |
| 单局时长 | 3–8 分钟；一"层"约 60–90 秒 |
| 操作复杂度 | 单指：点选方向 / 点选目标格；不要求精确摇杆操作 |
| 视角 | 固定正交相机（`Camera3D` 当前 `projection = Orthographic`，`size = 40`），等距 45° |

## 3. 核心循环

### 3.1 三层循环

```
[秒级] 探测前方 → 停下开挖 → 矿格消失 + 掉落 + 音效
			  ↑                              ↓
[分钟级] 燃油↓ / 货舱↑ → 判断：继续挖 or 回地表
			  ↓
[单局] 回地表结算 → 卖矿得金币 → 升级机器 → 下潜更深一层
```

### 3.2 各层循环的设计意图

| 层级 | 时长 | 玩家在做什么 | 设计目的 |
| --- | --- | --- | --- |
| 微循环 | 1–3 秒 | 看着挖掘机啃掉一格矿 | 提供持续的正反馈，构成"手感" |
| 中循环 | 30–90 秒 | 在油量/载重压力下决定推进路线 | 制造张力，避免变成无脑挂机 |
| 宏循环 | 3–8 分钟 | 回地表、卖矿、升级、再下潜 | 提供长期目标与成长感 |

### 3.3 关键节奏点

- **前 30 秒**：必须让玩家挖到第一格矿、看到第一次掉落与金币跳字。
- **第 1 次燃油告急**：安排在开局约 2 分钟，让玩家第一次做"回不回去"的决定。
- **第 1 次升级**：安排在第一次回地表后 10 秒内，保证"赚钱→变强"的因果链闭合。

## 4. 系统设计

### 4.1 矿区结构

矿区是一个 **三维格子场**，当前实现为 `GridMap` + 单一网格库（`Resources/ore_map.meshlib`）。

| 概念 | 定义 | 当前实现 |
| --- | --- | --- |
| 格（Cell） | 1×1×1 世界单位，矿区的最小单位 | `GridMap` 单元格，`set_cell_item(cell, item)` |
| 层（Layer） | 同一 Y 高度的一整片格 | 目前只填 `y = 0` 一层（`mine_field.gd`） |
| 岩层（Strata） | 按深度划分的硬度区间，决定挖掘耗时与产出 | ⚠ 待实现 |
| 矿脉（Vein） | 连续若干格的同种矿，视觉上带自发光标记 | 已用 `glowing_qiu.tscn` 沿 Z 轴标记矿脉位置 |

**岩层规划（建议）**：

| 深度（层） | 岩层名 | 硬度系数 | 主要矿物 | 视觉基调 |
| --- | --- | --- | --- | --- |
| 0–9 | 表土 | ×1.0 | 煤 | 暖褐、低对比 |
| 10–24 | 页岩 | ×1.6 | 煤、铁 | 冷灰、夹层线 |
| 25–49 | 玄武岩 | ×2.6 | 铁、铜 | 近黑、硬边高光 |
| 50+ | 结晶层 | ×4.0 | 稀有矿（发光） | 深黑 + 单点强调色 |

### 4.2 挖掘与行进

**当前原型行为**（`mineable_entity.gd`）：
1. `MOVING` 状态下沿 `forward_dir`（默认 `(-1, 0, 0)`）匀速前进；
2. 每帧把车头前方 `probe_distance = 1.8` 处换算成格子，若该格有矿 → 切 `MINING`；
3. 进入 `MINING` 后不再"空等"：按 `attack_interval`（默认 0.8s）用 `MineableData.attack` 一下一下攻击该格，扣 `Oredata.hp`，每一下发 `ore_damaged(cell, hp_left, hp_max)`；
4. 血扣到 0 → 清除该格，发 `ore_mined(cell, ore, value)` 与 `drop_gained(ore_name, value)`，并打印掉落价值，回到 `MOVING`。

> 查不到矿石数据、或攻击力 `<= 0` 时，退回旧的固定 `dig_time = 1.5s` 挖掘，保证不会卡死。

**目标设计**：

| 规则 | 说明 |
| --- | --- |
| 自动挖掘 | 玩家不需要"按住"挖矿键；对准方向后挖掘自动执行（P2：一次只做一个决定） |
| 单格单次 | 一次只挖一格，挖完自动继续前进，避免多格并发的表现混乱 |
| 挖掘耗时公式 | 命中次数 `hits = ceil(ore.hp / excavator.attack)`，`dig_time ≈ (hits - 1) × attack_interval` |
| 硬岩惩罚 | 硬度超过机器有效攻击力的 2 倍时，提示"需要升级钻头"，不允许硬啃（避免玩家卡死） |
| 不可挖格 | 基岩（地图边界）不可挖，用于限制活动范围 |

**朝向与转向**：允许四方向（±X / ±Z）转向，转向耗时 0.25s，期间不推进。不做自由旋转，保证正交视角下读图清晰。

### 4.3 燃油与经济压力

燃油是**唯一的硬约束**，用来制造中循环的取舍。

| 规则 | 数值（首版） |
| --- | --- |
| 油箱容量 | 100 |
| 油耗 | **4.0 / 秒固定**（前进、挖掘、原地不动都一样） |
| 一局时长 | 约 **25 秒**（100 ÷ 4.0），落在 20–30 秒目标区间 |
| 燃油耗尽 | 机器直接 `queue_free` 消失（**临时表现**），已入账金币保留 |
| 油量事件 | `fuel_changed(current, max)` 给 HUD 油条；`fuel_empty` 给后续结算/失败流程 |

> 设计意图：不惩罚失败，只惩罚"贪心"。⚠ 目前"耗尽 → 消失"只是占位，等回地表/结算系统做好后，应替换成"停在原地 + 结算"。

### 4.4 矿物与掉落

`Oredata` 已定义 `ore_name / hp / drop / value`：`drop` 是挖完一格的**产出数量**，`value` 是**每单位卖价**，单格金币 = `drop × value`。挖完时由 `MineableEntity._finish_mining()` 调 `Game.add_coins()` 入账。

**建议扩展字段**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `ore_name` | String | 显示名 |
| `hp` | float | 挖掘耐久（血量），被攻击扣到 0 即挖完 |
| `drop` | float | 掉落数量：挖完这一格产出多少单位 |
| `value` | float | 每单位金币单价（已实现），单格金币 = `drop × value` |
| `color` | Color | 粒子与 UI 高亮色 ⚠ 新增 |
| `rarity` | enum | 常见/稀有/史诗，控制音效与光效强度 ⚠ 新增 |

**首版矿表**：

| 矿 | hp | 单格金币 | 出现深度 | 说明 |
| --- | --- | --- | --- | --- |
| 煤 | 10 | 5 | 0+ | 基础矿，撑起前 3 次升级 |
| 铁 | 18 | 12 | 10+ | 中期主力 |
| 铜 | 22 | 18 | 25+ | 需要二级钻头 |
| 结晶 | 40 | 60 | 50+ | 发光、稀有，单格高回报 |

### 4.5 货舱与回程

| 规则 | 说明 |
| --- | --- |
| 货舱容量 | 初始 20 单位，升级可扩 |
| 满载行为 | 无法继续装矿，提示"回地表卸货"，但**仍可移动** |
| 回程方式 | 玩家主动点"回地表"，机器沿已挖通道快速返回（不消耗燃油，耗时 = 距离/回程速度） |
| 结算 | 到地表后自动卖出全部矿石，金币跳字 + 音效 |

> ⚠ 待定：是"回地表才结算"还是"随时可卖"。建议前者，回程本身构成节奏上的呼吸点。

### 4.6 升级与成长

成长系统的唯一购买出口是**技能树（4.6.1）**，不再设独立的机器改装面板（已于 v0.4 移除）。四个成长维度对应四个短板，全部落在技能树的四条分支上：

| 维度 | 解决的问题 | 升级项 | 效果 |
| --- | --- | --- | --- |
| 钻头 | 挖得慢 / 挖不动 | `attack` / `attack_interval` | 提升每次伤害与攻击频率（等效 DPS），解锁硬岩 |
| 油箱 | 挖不久 | `fuel_max` | 提升单局续航 |
| 货舱 | 装不下 | `cargo_max` | 提升单趟收益 |
| 引擎 | 跑得慢 | `speed` | 提升移动与回程速度 |

**成本曲线**：`cost(n) = base_cost × 1.55^n`（n 为已购买次数），保证每级成本约为上一级的 1.5 倍，与收益增长大致同步。数据定义 `Resources/Upgrades/*.tres` 与 `Game` 的等级接口保留，作为技能树节点扣费的数值来源。

#### 4.6.1 技能树（★ 核心特色系统）

技能树是本作区别于同类挖掘游戏的**特色系统**，玩家成长的主要出口之一，必须长期保留并持续扩充，任何重构都不得移除或降级它。

- **定位**：玩家数值成长与流派构筑的**唯一界面出口**——用金币在树上解锁节点，把机器拼成不同流派（速度流 / 收益流 / 后续的续航流等）。原独立的机器改装面板已移除（v0.4），其"买数值"职能并入技能树：节点自带 `effect_key / effect_value / cost`，扣费即购买。
- **位置**：`Scenes/UI/SkillTree/skill_tree.tscn`，实例化在 `Scenes/MiningField/control.tscn` 的 `SubViewport` 内，与 `MineField` 平行；由 `CanvasLayer(layer = 10)` 绘制在矿区画面之上。
- **开关**：`U` 键切换，右上角 `×` 关闭（`Scenes/MiningField/control.gd` 统一处理输入）。
- **结构**：由 `Resources/SkillTree/basic_skill_tree.tres` 数据驱动（`SkillTreeData` + `SkillNodeData`），节点支持方形 / 六边形两种形状，父子连线由 `SkillTree._draw()` 绘制。界面左侧预留「精通」「遗物」两个页签位，作为后续扩充入口。
- **树状结构**（`◆` 六边形关键节点 / `□` 方形数值节点；对齐参考图的四向发散布局：左上钻头、右上经济、左下引擎、右下续航）：

```
◆ 挖掘核心（root）────────────── 整棵树的起点，免费已解锁
│
├──【左上 · 钻头线】钻得快、挖得动（工程黄）
│   ├── □ 合金钻头 …… 单次伤害 +15%，80 金币
│   │   ├── □ 高频钻机 … 攻击间隔 −15%，200 金币
│   │   │   └── ◆ 破碎者 … 解锁硬岩开采，480 金币
│   │   └── □ 深孔钻 …… 高耐久矿伤害 +20%，120 金币
│
├──【左下 · 引擎线】跑得快、转向灵活（青绿）
│   ├── □ 涡轮引擎 …… 速度 +10%，120 金币
│   │   ├── □ 二级变速箱 … 速度 +15%，260 金币
│   │   ├── □ 液压转向 …… 转向耗时 −40%，220 金币
│   │   └── □ 惯性配重 …… 挖掘期间不减速，180 金币
│
├──【右上 · 经济线】卖得多、装得下（橙）
│   ├── □ 矿石精炼 …… 矿价 +10%，160 金币
│   │   ├── ◆ 精选熔炉 … 稀有矿价值 +100%，500 金币
│   │   └── □ 扩容货舱 … 货舱容量 +10，240 金币
│
└──【右下 · 续航线】挖得久、耗得省（蓝）
	├── □ 加大油箱 …… 油箱容量 +40，100 金币
	│   ├── □ 双油路 …… 燃油消耗 −15%，280 金币
	│   └── □ 低怠速系统 … 原地开挖油耗 −25%，200 金币
```

- **解锁规则**：必须先解锁父节点才能点子节点（`SkillTree._state_for()` 已实现）；每条线 2–3 层深度，四条线互不交叉。
- **现状**：四向 14 节点结构已进数据（`basic_skill_tree.tres`），布局、悬停、选中与右侧详情面板已跑通；解锁扣费与实际数值尚未接入。接入时读取节点的 `effect_key / effect_value / cost`，扣除金币（`Game.spend_coins`）后刷新 `SkillTree._state_for()`。
- **后续规划**：
  - 扩到 3 层以上深度、每层 2–3 个节点，至少 2 条完整流派；
  - 节点解锁状态写入存档（挂在 `Game` 单例的存档缺口上，见第 8 章）；
  - 稀有节点用更强的视觉强调（发光描边 / 专属图标），但同样遵守像素 HUD 风规范（见 4.8）。
- **视觉**：遵循 4.8 的像素 HUD 风：深紫底 + 星点背景、直角双层描边节点、连线硬边不抗锯齿；技能树整屏背景是少数允许"星空氛围"的界面。
- **运行形态**：本节只定义**数据结构与内容**（节点、效果键、费用）。它的界面、入口、货币与效果落地口径统一以 **4.10 改装终端**为准；两者冲突时以 4.10 为最新决策。

### 4.7 相机与操作

| 项 | 设计 |
| --- | --- |
| 相机 | 固定正交等距（现有 `Camera3D`，`size = 40`），不跟随旋转 |
| 跟随 | 相机平滑跟随挖掘机（`lerp`，阻尼 8–10），挖掘时轻微推近 ⚠ 可选 |
| 主操作 | 点击矿区右侧发光小球（落脚点标记）附近 → 吸附到最近的小球 → 在该点生成挖掘机并自动朝矿区推进；点得太远（超出 `spawn_snap_radius`）不生成 |
| 辅助操作 | 底部按钮：回地表、加速（长按）、暂停 |
| 反馈 | 挖掘时车身抖动 + 碎屑粒子 + 每格"咔"声；金币跳字 |

#### 4.8.1 三分区布局：左栏 / 右上主区 / 底栏

**窗口在架构上只有三块，任何界面都必须落在其中一块里，不许自建全屏层。**

```
┌───────────┬─────────────────────────────────────────┐
│           │                                         │
│   左栏     │        右上主区 = 主舞台（Stage）          │
│   373px   │        SubViewport 1547 × 802            │

│           ├─────────────────────────────────────────┤
│           │        底栏 278px（主行动 / 提示）         │
└───────────┴─────────────────────────────────────────┘
```

| 分区 | 尺寸（1920×1080 基准） | 谁的地盘 | 放什么 |
| --- | --- | --- | --- |
| **左栏** | 373 × 1080 | 窗口级 `HudLayer` | 金币、掘进深度、油量、货舱、导航 + 功能按钮列 |
| **右上主区** | 1547 × 802 | `SubViewportContainer → SubViewport` | **主舞台**：所有需要玩家操作的场景 |
| **底栏** | 1547 × 278 | 窗口级 `HudLayer` | **持有物 / 库存**（4.11，内容随场景切换）+ 提示行 |

**主舞台规则（硬规定）**

1. 凡是可交互的场景——矿区、**改装终端**、营地设施、熔炼站、商店——一律做成主区内的**子场景**，靠换子节点（必要时切相机）来切换，**外框不动**。禁止再开第二个全屏层承载玩法界面。
2. 主区内的子场景共享同一坐标系（1547 × 802）。**UI 按 1547 × 802 出设计稿，不按 1920 × 1080**；写 1920 基准的偏移会在主区里溢出。
3. 全屏层只允许一种例外：结算 / 过场这类**不可交互的临时遮罩**。
4. 窗口级 `HudLayer` 只放"跨场景常驻"的信息，不放任何场景专属操作。

> 反例记录：v0.7 曾把改装终端改成窗口级全屏 `CanvasLayer(20)`，理由是"主区太挤 + 像素字会被缩放"。这违反本节的三分区前提，v0.8 已纠正——主区挤就重排主区，不能把场景搬到全屏。

- **分辨率自适应（硬规定）**：`project.godot` 设设计基准 1920×1080 + `canvas_items` 拉伸 + `expand` 宽高比适配——任意窗口尺寸（含 1152×648）UI 整体等比缩放，不错位、不留黑边。主区容器用「锚满全屏 − 左 373 − 底 278」表达分区，不依赖具体窗口数。

### 4.10 改装终端（★ 技能树的运行形态）

> 版本：v0.6 立项。本节是 4.6.1 的落地口径，优先级高于 4.6.1 中关于界面与货币的旧描述。

#### 4.10.1 定位与命名

**改装终端**是技能树在运行时的**唯一界面形态**——一台摆在营地的机器，玩家靠它把节点一个个"安装"到挖掘机上。它不是一个独立于技能树的系统，而是同一份数据（`basic_skill_tree.tres`）的另一种读法。

命名统一（此前四处不一致，现收敛）：

| 场合 | 用词 |
| --- | --- |
| 玩家看到的界面标题 | **改装终端** |
| 文档正文提到这个界面 | 改装终端 |
| 指数据结构 / 节点集合 | 技能树 |
| 代码目录 | `Scenes/UI/SkillTree/`（沿用，不因改名迁移） |

#### 4.10.2 核心规则

| 项 | 决策 |
| --- | --- |
| 货币 | **只用金币**（沿用 `SkillNodeData.cost`）。`Game.skill_points` 不参与解锁，去向见 4.10.8 |
| 入口条件 | 仅当挖掘机处于**停靠**状态，或当前没有活动挖掘机时可打开 |
| 打开期间 | 矿区时间冻结：油耗、移动、挖掘全部暂停；关闭即恢复 |
| 解锁校验 | 父节点已解锁 **且** 金币 ≥ cost，两者缺一不可 |
| 解锁结果 | 扣费 → 写入解锁集合 → 立即存盘 → 刷新全树与 HUD 金币 |
| 回退 | 首版不支持退款、不支持重置 |
| 生效时机 | 下一次生成挖掘机时应用；停靠中的机器不热更新（改完再出发，语义自洽） |

#### 4.10.3 效果管线（★ 当前完全缺失的一层）

现状是两端悬空：节点数据有 `effect_key / effect_value`，实体直接读 `mineable_data` 原值，中间没有任何聚合。必须补第三层：

```
SkillNodeData（数据，.tres）
	  ↓  按已解锁集合过滤
SkillModifiers（聚合，运行时派生对象）
	  ↓  应用到一份复制的 MineableData
MineableEntity（消费，只读修饰后的副本）
```

**聚合公式（加算优先）**：

```
pct[key]  = Σ effect_value        # 同键多个节点直接累加
flat[key] = Σ effect_value        # 固定值类累加
final     = (base + flat) × (1 + pct)      # 减算类用 (1 − pct)
```

选择加算的理由：15 个节点若走连乘，满树时数值会指数级偏离 5 章的平衡表；加算可手算校验，也便于后续调平衡。减算类结果钳制下限（如 `attack_interval ≥ 0.05`）。

**效果键映射表**：

| effect_key | 目标 | 运算 | 状态 |
| --- | --- | --- | --- |
| `attack` | `MineableData.attack` | 百分比加算 | 批次 1 |
| `attack_interval` | `attack_interval` | 百分比减算，下限 0.05s | 批次 1 |
| `tough_ore_damage` | 攻击力（条件） | 目标 `hp ≥ 18` 时追加 | 批次 1 |
| `excavator_speed` | `speed` | 百分比加算 | 批次 1 |
| `fuel_max` | `total_fuel` | 固定值加算 | 批次 1 |
| `fuel_burn` | `fuelConsumptionPerSecond` | 百分比减算 | 批次 1 |
| `idle_burn` | 挖掘态油耗（仅 `MINING`） | 百分比减算 | 批次 1 |
| `cargo_max` | 新增 `cargo_max` 字段 | 固定值加算 | 批次 1 |
| `ore_value` | 结算 `drop × value` | 百分比加算 | 批次 1 |
| `ore_value_flat` | 结算单价 | **固定值加算**：`drop × (value + flat) × (1 + pct)` | v0.13.1 |
| `core` | — | 无效果，仅作起点 | 批次 1 |
| `hard_ore_unlock` | 硬岩判定 | 布尔 | 批次 2（缺硬岩机制） |
| `rare_value` | 稀有矿结算 | 百分比加算 | 批次 2（缺 `Oredata.rarity`） |
| `turn_speed` | 转向时长 | 百分比减算 | 批次 2（缺四向转向） |
| `no_slow_dig` | 挖掘减速 | 布尔 | 批次 2（缺减速机制） |

> 批次 2 的四项**依赖尚不存在的机制**，不是数值问题。它们对应的节点在终端里照常显示，但状态为 `! 系统未就绪` 且禁止购买——不隐藏，保持树的完整形状与后续目标感。

#### 4.10.4 节点状态机

数据层只有三态，UI 再派生出两个"可读但不可买"的态：

| 状态 | 判定 | 表现 |
| --- | --- | --- |
| `UNLOCKED` | id 在已解锁集合内 | 实心节点，`[已安装]`，按钮禁用 |
| `AVAILABLE` | 父节点已解锁、自身未解锁、未命中 pending | 高亮描边，`[安装]` |
| `LOCKED` | 父节点未解锁 | 暗态，`需要先安装：<父节点名>` |
| `UNAFFORDABLE` ★UI | `AVAILABLE` 且金币不足 | 按钮`余额不足`，按钮上费用转暗并补一行亮琥珀「还差 N」（色板无红色，不用红） |
| `MECHANIC_PENDING` ★UI | 命中批次 2 的四个键 | 按钮`系统未就绪`，费用隐藏，禁用 |

判定顺序固定为：**已安装 → 前置 → 机制未就绪 → 金额**。代码落在 `SkillTree._detail_state_for()` 与 `Game.can_unlock_skill()`，两处口径必须一致。

**费用展示规则（v0.8.1 修正）**：费用**直接压在安装按钮上**（按钮左端是动作词，右端是费用，右对齐；余额不足时在费用下方加一行「还差 N」）。费用不放进详情面板的元信息行——元信息行只放静态事实（前置 / 当前余额 / 所在分支），扣费数字属于「决策信息」，必须长在玩家要按的那个键上。

#### 4.10.5 入口门槛：停靠

营地场景（4.9 `CAMP`）尚未实现，因此首版用**停靠**作为等价的最小门槛：

- `MineableEntity` 新增 `dock()`、`is_docked`、`docked` 信号；停靠时清零速度、暂停状态机、**停止烧油**。
- HUD 右下角原「回地表」占位改为「**停靠**」，触发 `dock()`。
- 未停靠时按 `U`：终端不打开，HUD 提示一行「需先停靠」。
- 过渡说明：停靠 = "就地驻车"，是回营地流程的轻量替代。等 `CAMP` 场景做好，停靠变成回营地的终态，**终端 UI 原样复用**，不需要重做。

> 这一条同时修掉一个现有隐患：当前 `_toggle_skill_tree()` 只切可见性，3D 侧照常 4.0/秒烧油，玩家看树会烧到 `queue_free`。

#### 4.10.6 视觉：琥珀单色 CRT

**为什么是琥珀而不是绿色荧光**：6.1 规定全画面只保留工程黄 `#D9A227` 一个高饱和色。绿色 CRT 会引入第二个强调色，直接违反色板纪律；琥珀磷光正好复用工程黄，同色系不破纪律，且"琥珀终端"本身就是 80 年代工控机的经典形态。

| --- | --- |
| 底色 | `#05040A`（屏外）/ `#0B0A12`（屏内） |

| 正文文字 | `#F0EEE4`；可交互项用荧光色 |
| 扫描线 | 1px 亮 / 3px 暗交替，不透明度 8%，**静止不滚动**（滚动会破坏像素稳定性） |

扫描线由叠在最上层的 `CanvasItem` shader 实现，`mouse_filter = IGNORE`，不影响点击。

| 右下 | 表单：ID / 名称 / 前置节点 / 解锁花费 / 可升级次数 / 效果类型（下拉目录 + 自定义键）/ 效果数值（百分比按 % 输入）/ **效果说明**（手填则游戏内原样显示，留空按类型自动生成）/ 描述 / **实现备注**（写给程序看，不显示）/ 形状 |
| 工具栏 | 打开 / 保存 / 新建分支 / 新建节点 / 删除（级联，确认）/ 自动布局（按分支方向重算坐标）/ 撤销（快照式，60 步） |

**分支口径**：分支 = 根节点的直系子节点；"技能属于哪个分支"由前置节点决定（前置选根 = 分支头），分支名 = 分支头节点名。效果键目录在 `addons/skill_tree_editor/effect_catalog.gd`，**新增键要同步登记 `SkillModifiers` 的三张表才会真正生效**。

> 事故记录（2026-11-12）：`basic_skill_tree.tres` 曾被整体清空（172 行节点丢失，疑似编辑器占用时被写坏），已从 Git 恢复。插件的空树保存确认 + `.bak` 备份即为针对此事故的防护。

### 4.11 底栏：持有物 / 库存（★ 底栏内容规范）

> 版本：v0.9 立项。底栏不再只放按钮，而是「玩家拥有的东西」的常驻栏。

#### 4.11.1 定位与场景切换

底栏（1547 × 278，窗口级 `HudLayer`）显示**玩家当前拥有的资产**，内容由主舞台场景决定：

| 主舞台场景 | 底栏显示 | 状态 |
| --- | --- | --- |
| 一号坑（矿区） | 拥有的挖掘机 | ✅ 已实现 |
| NPC 任务场景 | 库存物品 | ⬜ 暂不实现，仅换数据源 |

**数据源协议**：底栏 UI 只认识 `InventorySlot` 槽位结构，不认识任何业务。主舞台子场景实现五个方法，`control.gd` 统一绑定与刷新：

```
get_inventory_context()        # 场景标签，如「一号坑 · 挖掘机」
get_inventory_hint()           # 提示行文案
get_inventory_slots()          # Array[InventorySlot]
get_selected_slot_index()      # 当前选中槽位，-1 = 无
on_inventory_slot_activated(i) # 槽位被点击
```

换场景 = 换数据源（`control._set_bar_source()`），底栏代码不改。

#### 4.11.2 矿场：挖掘机槽位

- **持有模型**：`Game.excavators : Array[ExcavatorUnit]`，一台机器一个条目（`data` 指向共享的 `MineableData`，`deployed` 为运行态）。
- **槽位两态**：`在库 · 点击选中`（灰紫描边，可点击选中）/ `出勤中`（暗琥珀描边 + 图标压暗，不可再派遣）。
- **派遣**：点击槽位选中 → 点击矿区发光小球附近生成；**不选中直接点矿区 = 自动派第一台在库机器**（保留原型手感）。同一时间场上只有一台。
- **起步机**：首次游玩（或存档里一台都没有）自动送一台「小型挖掘机 01」。

#### 4.11.3 回收规则（★ 本节核心）

| 触发 | 行为 |
| --- | --- |
| **挖空这一行**：机器沿前进方向走到场地包围盒外、且前方无矿（`row_finished` 信号） | 自动回库，槽位变回「在库」 |
| **燃油耗尽** | **直接报废销毁**，库存里那一台也一并移除（机器没了就是没了；机库空了只能等入手新机器） |

出勤状态不入档：读档后所有机器一律回库（存档只存机器的资源路径）。

#### 4.11.4 视觉

沿用 4.8 像素 HUD 风：`UI_Frame_HUD.png` 机框、槽位直角双层描边（禁圆角软阴影）、选中态工程黄 2px 描边、文字硬投影；图标暂用 `basic_mini_excavator.png`（AtlasTexture 裁掉水印），美术资源到位后替换。

#### 4.11.5 验证

`Tools/inventory_selftest.gd`：起步机兜底、派遣/回库切换、报废移除、存档往返（重建 + 全部回库）、旧档兼容五项。跑法 `godot --headless --path . --script res://Tools/inventory_selftest.gd`。引擎截图：`Docs/Previews/bottom_bar_ingame.png`。

#### 4.12.1 主区三视图

同一块 1547 × 802 主区，三种视图互斥切换（`control.gd` 状态机）：

| 视图 | 内容 | 容器 |
| --- | --- | --- |
| **ORBIT** 地球全景 | 地球 + 表面地点标记，选地点进入 | `OrbitViewContainer`（独立 SubViewport + own_world_3d，不与矿场抢环境） |
| **MINE** 矿场 | 现有矿区玩法 | `SubViewportContainer` + MineField |

#### 4.12.2 转场（来回都要短，0.3~0.45 秒）

| 方向 | 动作序列 |
| --- | --- |
| 进矿场 | 黑幕淡入 0.14s → 切视图（矿场相机置于远景）→ 黑幕淡出 0.14s，同时相机 130 → 40 收拢 0.18s（"落进矿区"） |
| 出矿场 | 矿场相机 40 → 130 拉远 0.18s（"场景缩小"）→ 黑幕 0.14s → 切地球全景、淡出 0.16s |

转场期间锁输入（`_busy`），连点不会打乱状态机。

#### 4.12.3 左栏地球小窗：CRT 开关机 + 无信号雪花

- **地球全景时小窗熄灭**（右侧已经是地球，不重复）；进矿场 / 终端时点亮。用户明确：小窗先不显示当前地点。
- **关机**（古早电视）：白闪 0.07s → 纵向压成一条亮线 0.14s → 横向收成一个点 0.07s → **接上"无信号"雪花屏**（横向弹开 0.09s 铺满）。
- **开机**：雪花噪点先闪掉 0.05s → 从一条亮线展开 0.08 + 0.11s，配白闪消退与「地球」字幕淡入。
- 启动时的初始熄灭是瞬切，不播动画（第一帧没有"关机"的语义）。
- 雪花屏是程序化 shader（`Shaders/crt_static.gdshader`）：粗颗粒随机噪点 + 扫描线 + 缓慢上滚亮带，不吃贴图。
- 小窗熄灭时 `SubViewport.render_target_update_mode = DISABLED`，不让一颗看不见的星球继续占 GPU。

#### 4.12.4 地点标记：拖拽地球，点黄点进入

- 数据：`Datas/Locations/location_definition.gd`（球面方向 × 半径 + 名称 + 目标视图），现有 `pit_01`（矿场 1 号）与 `upgrade_terminal` 两份 .tres；以后加深井 / 熔炼站只加资源。
- **地球不自转**：由玩家按住左键拖动旋转（水平 = 绕地轴，竖直 = 俯仰，俯仰限幅 ±1.15rad）；松手带轻微惯性后停下，不无限打转。
- **黄点即点击目标**：自发光小方块立在球面法线上，命中判定是屏幕空间 18px 半径（比视觉大一圈），悬浮时方块微微胀大 + 指针变手型。
- **标签默认隐藏**：只有鼠标悬浮在那颗点上时才显示（名称 + 编号副行），转到球背面或移开即消失。
- 点击与拖动互斥：按下到松开的位移小于 8px 且仍停在同一颗点上才算点击，拖完松手不会误进场景。

#### 4.12.5 左栏「退」按钮

按钮列新增「退」（在「技」上方）：仅在 MINE 视图显示，点击回到地球全景；ESC 在矿场 / 终端里等效。

## 5. 数值框架

### 5.1 核心公式

```
命中次数    hits       = ceil(ore.hp / excavator.attack)
挖掘耗时    dig_time   = (hits - 1) × attack_interval
每秒油耗    burn_rate  = excavator.fuelConsumptionPerSecond
单局时长    run_time   = fuel_max / burn_rate
单格油耗    fuel_cost  = dig_time × burn_rate
单格收益    income     = ore.drop × ore.value
升级成本    cost(n)    = base_cost × 1.55^n
```

### 5.2 初始值表

| 参数 | 初始值 | 上限（首版） |
| --- | --- | --- |
| `attack`（单次伤害） | 8 / 次 | 96 |
| `attack_interval`（攻击间隔） | 0.8 秒 | 0.3 秒 |
| 等效 `power` | 10 / 秒（= 8 / 0.8） | 120 |
| `fuel_max` | 100 | 400 |
| `fuelConsumptionPerSecond` | 4.0 / 秒 | — |
| 初始一局时长 | 约 25 秒 | — |
| `cargo_max` | 20 | 200 |
| `speed` | 10 单位/秒（沿用现有资源） | 25 |
| `probe_distance` | 1.8（沿用现有值） | — |

### 5.3 平衡目标（验收用）

一局标准流程应满足：

- [ ] 第一局：能挖 25–35 格，赚到 150–250 金币，够买 1 次升级。
- [ ] 第三局：能稳定推进到 10 层以下，看到第一种新矿。
- [ ] 第十局左右：解锁二级钻头，能挖铁/铜。
- [ ] 任意时刻：玩家不会因为"挖不动"而卡死超过 1 分钟。

> 数值全部走 `Resource`（`.tres`），改表不改代码。⚠ 建议把矿物表从单文件拆成 `Resources/Oredata/*.tres` 数组，由 `mine_field.gd` 按深度权重抽取。

## 6. 美术与音频方向

### 6.1 美术

- **风格**：16-bit 复古像素 + 3D 低模混搭；等距 45° 正交视角。
- **色板**：严格遵循 `Docs/ArtPrompts/mining_pixel_prompt_pack.md` 第 1 节，**全画面只保留工程黄一个高饱和色**。

- **发光物**：矿脉用 `glowing_qiu.tscn` 这一类自发光小体块标记，仅稀有矿使用。

### 10.1 术语表

| 术语 | 含义 |
| --- | --- |

| 中循环 | 单局内 30–90 秒的决策节奏 |
| 宏循环 | 跨越单局的"挖→卖→升级"循环 |
